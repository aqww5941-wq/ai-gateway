# Changelog 记录规范

本目录保存面向工程审计的逐任务变更记录，不替代面向发布用户的版本 Release Notes。

## 文件命名

```text
YYYYMMDD-HHmm-<lowercase-kebab-slug>.md
```

时间使用 Asia/Shanghai。一个实现任务对应一个文件，并与代码放在同一 Git 提交中。

## 适用范围

以下变化必须创建记录：代码、配置契约、数据库、API、构建/部署行为、测试行为、工程规则。纯阅读、分析或无文件修改的审查不创建。

## 模板

```markdown
# 变更标题

- 日期：YYYY-MM-DD HH:mm CST
- 类型：L1 / L2 / L3 / L4
- 关联需求：需求编号或 N/A
- 影响模块：路径或模块

## 根因

说明问题为何发生，指出失效的职责、状态或契约，不只描述表面现象。

## 解决方案

说明采用的完整方案、关键取舍，以及为什么能消除根因。

## 行为与兼容性

说明 API、配置、数据、错误、性能和用户体验是否变化。

## 可观测性

说明新增或调整的日志、指标、Trace；没有运行时变化时写“不适用”。

## 验证

- `[通过]` 实际执行的命令或检查
- `[未执行]` 未执行原因
- `[失败]` 失败结果和影响

## 风险与回滚

说明剩余风险、回滚方法和是否涉及数据迁移。
```

不要填写当前提交 SHA；文件本身与实现位于同一提交，避免为补写 SHA 产生额外提交。
