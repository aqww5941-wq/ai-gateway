# 建立 Agent 项目引导与工程治理规则

- 日期：2026-08-05 18:12 CST
- 类型：L1
- 关联需求：N/A（工程治理基线）
- 影响模块：`AGENTS.md`、`.rules/`、`changelog/`、`docs/`

## 根因

仓库此前没有根 `AGENTS.md` 和场景化规则索引。新对话只能从 README 和当前代码推断方向，无法稳定识别“当前实现”与 v2 Approved Baseline 的差异，也没有强制流程保证修改前完成根因分析、读取相关设计、补充诊断日志、生成变更记录和提交 Git。

同时，项目包含配额 Fail Open、Redis/Store 自动回退和协议能力 Fallback 等高风险场景。如果只写“保持稳定”或“禁止降级”等抽象口号，Agent 容易在故障转移与静默丢能力之间做出错误判断。

## 解决方案

- 新增根 `AGENTS.md`，作为所有新对话的项目入口、执行顺序和场景规则路由表。
- 将通用项目介绍、根因分析、交付流程和可观测性规则拆入 `.rules/` 核心层。
- 按 Go 后端、React 前端、Provider 协议、路由韧性、配置热重载、存储安全和 ADR 文档建立场景规则。
- 明确定义合法韧性机制与偷懒式降级的边界：降级必须显式、能力等价、可观测、可恢复，且不能破坏安全、账务、租户或协议语义。
- 建立每次实现变更对应一份 Markdown 记录的 `changelog/` 约定，并定义只暂存任务文件的自动 Git 提交流程。
- 将现有 v2 重构设计文档纳入同一治理基线，使新 Agent 可以稳定读取 Approved Baseline。

## 行为与兼容性

本次只新增工程治理和文档文件，不修改运行时代码、配置、API、数据库或构建产物。后续 Agent 默认在完成代码修改、验证和 changelog 后创建本地 Git 提交，但不会自动 push。

## 可观测性

没有运行时变化。规则新增了结构化调试日志的级别、字段、敏感信息、关键决策点以及日志/指标/Trace 分工要求。

## 风险与回滚
